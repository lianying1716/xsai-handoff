# 会话交接模板

`scripts/handoff.mjs new` 生成的骨架就是下面这套结构。填写时删掉示例说明，只留真实内容；某一节确实为空就写「无」，不要留空。

```markdown
---
created: <ISO 时间>
topic: "<一句话主题>"
project: "<项目名>"
cwd: "<生成时的目录>"
git_root: "<git 根，或 null>"
git_remote: "<origin 地址，或 null>"
---

# 会话交接

## 任务目标

这次要达成什么，一到三句话。

## 当前状态

现在停在哪一步。能做验证的就给证据：命令、退出码、产物路径。

## 关键决策与理由

- 决策：<做了什么选择>；理由：<为什么>；依据：<ADR/commit/issue 路径或 URL>

## 已完成工作

- <已落地的事项>（证据：<路径 / commit / 命令输出>）

## 剩余任务 / 下一步

1. <接手后第一个动作>
2. <之后的动作>

## 已知坑

- <踩过的雷 / 不要再走的弯路>

## 相关文件与链接

- <路径或 URL>（只引用，不复制正文）

## 建议技能

- <下一个会话应调用的技能名>：<为什么>
```

## 脱敏清单

写入前逐项检查并替换为占位符：

| 类型 | 例子 | 占位符 |
|---|---|---|
| API key | `sk-...`、`xsai_operator_...` | `<redacted:api-key>` |
| Token | 运营 token、OAuth token、会话 Cookie | `<redacted:token>` |
| 密码 / 私钥 | 密码、`.pem`、`.key` 内容 | `<redacted:secret>` |
| 个人身份信息 | 身份证号、手机号、邮箱、住址 | `<redacted:pii>` |

## 判断标准

接手的人**不打开原会话**，只读这份文档，就能知道下一步该做什么，这份交接就算合格。
